# FWMgr

**FireWall Manager** — интерактивный менеджер входящего firewall для Linux.

FWMgr работает с **UFW** и **nftables**, поддерживает IPv4/IPv6, белые и черные списки, онлайн-источники IP/CIDR и старается не изменять правила, созданные вручную или другими программами.

> [!WARNING]
> Любое изменение firewall на удалённом сервере может привести к потере доступа. Перед первым использованием рекомендуется иметь резервный доступ через консоль/VNC/IPMI или snapshot.

## Быстрая установка

Через curl:

```bash
curl -fsSL https://github.com/MaXa0H/fwmgr/releases/latest/download/install.sh | bash
```

Через wget:

```bash
wget -qO- https://github.com/MaXa0H/fwmgr/releases/latest/download/install.sh | bash
```

После установки:

```bash
fwmgr
```

Установленная копия находится в:

```text
/usr/local/lib/fwmgr/fwmgr.sh
/usr/local/bin/fwmgr -> /usr/local/lib/fwmgr/fwmgr.sh
```

## Возможности

- UFW и nftables
- IPv4 и IPv6
- отдельные IP и CIDR-подсети
- черный список
- белый список
- режим без ограничений FWMgr
- DROP / REJECT
- автоматическое определение текущего SSH-IP
- защита от случайной блокировки собственного SSH-подключения
- отображение сторонних правил firewall в режиме только чтения
- импорт и экспорт настроек
- онлайн-источники для blacklist и whitelist
- IP, CIDR и диапазоны `IP-IP` в онлайн-списках
- автоматическое преобразование диапазонов в CIDR
- независимый интервал обновления онлайн blacklist/whitelist
- last-known-good кэш онлайн-источников
- автоматические обновления списков через systemd timer
- обнаружение потенциально конфликтующих firewall
- защита от одновременного запуска нескольких экземпляров через `flock`
- автоматическая проверка новой версии FWMgr
- обновление через GitHub Releases
- обновление из локально скачанного более нового `fwmgr.sh`
- полное удаление собственных правил и файлов FWMgr

## Главное меню

Пример:

```text
Firewall: установлен
Backend FWMgr: nftables
Режим списков: белый
Отклонение соединений: DROP
Кол-во IP/подсетей в черном списке: 3
Кол-во IP/подсетей в белом списке: 5
Ваш IP адрес: 203.0.113.15

1. Переключить режим (выкл/черный/белый)
2. Отклонение соединений (DROP/REJECT)
3. Черный список
4. Белый список
5. Экспорт/импорт настроек
6. Сохранить
7. Удалить FWMgr
8. Проверить обновления FWMgr
9. Установить Firewall
0. Выход
```

Если поддерживаемый firewall отсутствует, пункты настройки недоступны до установки UFW или nftables. После установки firewall FWMgr остаётся в режиме **выключен** и сам не вводит ограничений.

## Режимы

### Выключен

FWMgr не вводит собственных ограничений. Существующие правила системы продолжают работать как раньше.

### Черный список

Адреса и подсети из blacklist блокируются. Остальные источники FWMgr не блокирует.

Белый список имеет приоритет как исключение из blacklist. Это используется в том числе для защиты административного SSH-IP.

### Белый список

Новые входящие соединения принимаются FWMgr только от источников, покрытых whitelist. Остальные блокируются выбранным действием DROP или REJECT.

Разрешение FWMgr не отменяет запреты других firewall-правил. Если существующее стороннее правило запрещает соединение, FWMgr его не обходит.

## DROP и REJECT

**DROP** молча отбрасывает пакет. Для удалённой стороны это больше похоже на недоступный сервер/порт.

**REJECT** явно сообщает удалённой стороне об отклонении соединения.

Исходящий трафик FWMgr не ограничивает.

## Списки

В каждом списке отображаются:

1. сторонние правила firewall — серым цветом и только для просмотра;
2. ручные правила FWMgr — с собственной нумерацией;
3. количество записей из онлайн-кэша, если онлайн-списки включены.

Сторонние правила нельзя удалить через FWMgr.

Поддерживаются:

```text
192.0.2.15
198.51.100.0/24
2001:db8::1
2001:db8:1234::/48
```

При ручном добавлении можно использовать пробелы, запятые или многострочный ввод. Дубликаты пропускаются.

Подсети нормализуются. Например:

```text
192.168.1.123/24
```

сохраняется как:

```text
192.168.1.0/24
```

## Онлайн-списки

В меню blacklist:

```text
4. Блокировка адресов из онлайн-списков: включена/отключена
5. Обновление списков: N минут
6. Менеджер онлайн-списков
```

В whitelist аналогично используется разрешение адресов из онлайн-списков.

Интервал по умолчанию:

```text
1440 минут
```

Blacklist и whitelist имеют независимые интервалы.

Менеджер источников:

```text
1. Добавить URL
2. Удалить URL
3. Очистить список URL
4. Обновить кэш сейчас
0. Назад
```

Разрешены `http://` и `https://` URL на raw-текстовые списки.

Поддерживаемые элементы онлайн-файлов:

```text
203.0.113.10
203.0.113.0/24
203.0.113.10-203.0.113.50
2001:db8::1
2001:db8::/48
```

Диапазоны автоматически преобразуются в минимальный набор CIDR.

Для каждого URL используется отдельный **last-known-good cache**: если источник временно недоступен или вернул невалидные данные, последний успешно полученный кэш не заменяется пустым.

Ограничения одного источника:

- до 10 MiB скачанных данных;
- до 200 000 нормализованных записей.

После сохранения автоматическое обновление выполняется через отдельные systemd timers для blacklist и whitelist.

## SSH-защита

FWMgr пытается определить IP текущего подключения через:

```text
SSH_CONNECTION
SSH_CLIENT
```

Перед сохранением:

- текущий SSH-IP удаляется из ручного blacklist, если конфликтует с ним;
- текущий SSH-IP гарантированно покрывается ручным whitelist;
- если whitelist уже содержит подходящую подсеть, лишняя точечная запись не создаётся.

Это также защищает SSH-IP от будущего попадания в автоматически обновляемый blacklist, поскольку whitelist является приоритетным исключением.

Если текущий SSH-IP определить невозможно, автоматическая защита не применяется.

## Существующие правила firewall

FWMgr не очищает весь ruleset и не использует:

```bash
iptables -F
nft flush ruleset
```

### nftables

FWMgr создаёт отдельную таблицу:

```text
table inet fwmgr
```

При выключении/удалении удаляется только собственная таблица FWMgr.

### UFW

FWMgr использует собственную цепочку и помеченные блоки в framework-файлах UFW. При удалении удаляются только блоки между маркерами FWMgr.

Перед изменением создаются резервные копии затрагиваемых файлов.

Если маркеры FWMgr повреждены, скрипт не пытается угадывать границы и прекращает потенциально опасное удаление.

## Docker и контейнеры

FWMgr предназначен для входящего трафика непосредственно к самому хосту и намеренно не управляет:

```text
FORWARD
OUTPUT
PREROUTING
POSTROUTING
DOCKER
DOCKER-USER
NAT
```

Поэтому порты контейнеров, опубликованные Docker через `-p` / `ports:`, могут проходить через FORWARD и не ограничиваться whitelist/blacklist FWMgr.

Это поведение сделано намеренно, чтобы не вмешиваться в Docker, RemnaNode и другие контейнерные решения.

## Обнаружение firewall

FWMgr проверяет наличие/активность:

- UFW
- nftables
- firewalld
- netfilter-persistent
- Docker
- Fail2ban

Docker и Fail2ban отображаются как другие владельцы Netfilter и сами по себе не считаются конфликтом.

При потенциально конфликтующей конфигурации FWMgr сообщает об этом и не отключает сторонний firewall автоматически.

## Импорт и экспорт

Поддерживается:

```text
1. Экспортировать в файл
2. Экспортировать в виде строки
3. Импорт из файла
4. Импорт из строки
```

Экспорт содержит:

- версию формата;
- режим;
- DROP/REJECT;
- ручной blacklist;
- ручной whitelist;
- URL онлайн blacklist/whitelist;
- включение онлайн-списков;
- интервалы обновления.

Backend не привязывается к экспорту, поэтому конфигурацию можно переносить между сервером с UFW и сервером с nftables.

Онлайн-кэш не экспортируется — на новой машине он загружается заново.

Формат v2 обратно совместим с импортом старого формата v1.

## Хранение данных

Основная конфигурация:

```text
/etc/fwmgr/
```

Кэш онлайн-списков и резервные данные:

```text
/var/lib/fwmgr/
```

Кэш проверки обновлений:

```text
/var/cache/fwmgr/
```

Установленный скрипт:

```text
/usr/local/lib/fwmgr/fwmgr.sh
```

## Обновление FWMgr

При запуске установленный FWMgr периодически проверяет последний GitHub Release. Результат кешируется, чтобы не обращаться к GitHub при каждом запуске.

Принудительная проверка/обновление:

```bash
sudo fwmgr --update
```

Обновление проверяет:

- корректность файла `VERSION`;
- совпадение `VERSION` с `VERSION="..."` внутри `fwmgr.sh`;
- синтаксис нового скрипта через `bash -n`.

После этого системная копия заменяется атомарно.

### Обновление без доступа к GitHub

Если новая версия `fwmgr.sh` скачана вручную, её можно запустить:

```bash
sudo bash ./fwmgr.sh
```

Если файл новее установленной версии, FWMgr предложит обновить системную копию.

Автоматический downgrade более старым файлом не выполняется.

## Удаление

Удаляются только собственные компоненты FWMgr:

- таблица `inet fwmgr`;
- помеченные блоки UFW;
- systemd service/timer FWMgr;
- конфигурация и online-кэш;
- резервные копии FWMgr;
- установленный скрипт и команда `fwmgr`.

Пакеты UFW/nftables автоматически **не удаляются**, поскольку после установки их уже могут использовать другие программы.
