# fwmgr

Интерактивный менеджер Firewall для Linux.

Удобное управление белыми и черными списками IP-адресов и подсетей без необходимости вручную редактировать правила Firewall.

Менеджер работает с **UFW** и **nftables**, поддерживает IPv4 и IPv6 и старается не вмешиваться в правила, которые были созданы вручную или другими программами.

После установки запуск выполняется простой командой:

```bash
sudo fwmgr
```

## Возможности

* Работа с **UFW**
* Работа с **nftables**
* Поддержка **IPv4**
* Поддержка **IPv6**
* Поддержка отдельных IP-адресов
* Поддержка CIDR-подсетей
* Белый список
* Черный список
* Режим без ограничений
* Переключение между `DROP` и `REJECT`
* Автоматическое определение IP текущего SSH-подключения
* Защита от случайной блокировки собственного SSH-подключения
* Импорт и экспорт настроек
* Экспорт конфигурации в файл
* Экспорт конфигурации одной строкой
* Импорт конфигурации из файла
* Импорт конфигурации из строки
* Автоматическая нормализация IP-адресов и подсетей
* Автоматическое игнорирование дубликатов
* Сортировка IP-адресов и подсетей
* Обнаружение потенциально конфликтующих Firewall
* Отображение правил, созданных не через FWMgr
* Защита от одновременного запуска нескольких экземпляров FWMgr
* Установка системной команды `fwmgr`
* Простое обновление установленной версии

## Режимы работы

FWMgr поддерживает три режима.

### Выключен

FWMgr не вводит никаких ограничений.

Сервер работает так, как будто FWMgr не установлен.

При этом существующие правила UFW, nftables и других программ продолжают работать как обычно.

### Черный список

Все входящие подключения разрешены, кроме IP-адресов и подсетей, находящихся в черном списке FWMgr.

Например:

```text
192.0.2.15
198.51.100.0/24
2001:db8:1234::/48
```

### Белый список

FWMgr разрешает входящие подключения только с IP-адресов и подсетей из белого списка.

Остальные входящие подключения блокируются.

Например:

```text
92.255.196.106
95.105.71.197
192.168.0.0/16
2001:db8::/32
```

При этом существующие правила Firewall продолжают действовать.

Если какой-либо IP разрешен в FWMgr, но запрещен существующим правилом UFW или nftables, FWMgr не будет обходить этот запрет.

## DROP и REJECT

FWMgr позволяет выбрать способ блокировки соединений.

### DROP

Пакет молча отбрасывается.

Удаленная сторона не получает ответа.

Снаружи это больше похоже на ситуацию, когда сервер или порт вообще недоступен.

### REJECT

Соединение явно отклоняется.

Удаленная сторона получает ответ о том, что соединение невозможно.

Выбор выполняется непосредственно из главного меню FWMgr.

## Существующие правила Firewall

FWMgr не должен становиться владельцем всей конфигурации Firewall.

Правила, которые были добавлены:

* вручную;
* через UFW;
* через nftables;
* Docker;
* Fail2ban;
* 3x-ui;
* другими программами;

не удаляются и не становятся правилами FWMgr.

В интерфейсе такие правила отображаются отдельно и выделяются серым цветом.

Они доступны только для просмотра и не участвуют в нумерации правил FWMgr.

Удалять через FWMgr можно только те записи, которые были добавлены самим FWMgr.

## UFW

При использовании UFW FWMgr создает собственную цепочку и собственные помеченные секции конфигурации.

Существующие пользовательские правила UFW не перезаписываются.

При отключении FWMgr удаляются только принадлежащие ему правила.

## nftables

При использовании nftables FWMgr создает отдельную таблицу:

```text
table inet fwmgr
```

FWMgr не выполняет:

```bash
nft flush ruleset
```

и не очищает существующие таблицы nftables.

Удаление или отключение FWMgr затрагивает только таблицу `inet fwmgr`.

## SSH-защита

Перед сохранением конфигурации FWMgr пытается определить IP текущего SSH-подключения через:

```text
SSH_CONNECTION
SSH_CLIENT
```

Если текущий IP находится в черном списке, FWMgr автоматически удалит конфликтующую запись.

Если включен белый режим, а текущий SSH-IP отсутствует в белом списке, он будет автоматически добавлен.

Если IP уже разрешен более широкой подсетью, дополнительная запись не создается.

Например, если SSH-подключение идет с:

```text
192.168.1.50
```

а в белом списке уже находится:

```text
192.168.1.0/24
```

ничего добавляться не будет.

Если определить IP SSH-подключения невозможно, автоматическая защита не применяется.

> [!WARNING]
> Работа с Firewall на удаленном сервере всегда несет риск потери доступа. Перед первым использованием рекомендуется иметь доступ к консоли/VNC панели хостинга или snapshot сервера.

## IPv4 и IPv6

Черные и белые списки одновременно поддерживают IPv4 и IPv6.

Примеры IPv4:

```text
203.0.113.15
203.0.113.0/24
```

Примеры IPv6:

```text
2001:db8::1
2001:db8:1234::/48
```

При использовании UFW активный режим FWMgr требует включенной поддержки IPv6 в UFW.

Если IPv6 в UFW отключен, FWMgr не будет создавать ложное ощущение, что сервер защищен одновременно по IPv4 и IPv6.

## Нормализация подсетей

FWMgr автоматически приводит сети к каноническому виду.

Например:

```text
192.168.1.123/24
```

будет сохранено как:

```text
192.168.1.0/24
```

А записи:

```text
192.168.1.5
192.168.1.5/32
```

рассматриваются как один и тот же адрес.

То же самое применяется к IPv6.

## Docker и контейнеры

FWMgr управляет входящими соединениями непосредственно к самому серверу.

Он намеренно не изменяет:

```text
FORWARD
OUTPUT
PREROUTING
POSTROUTING
DOCKER
DOCKER-USER
NAT
```

Это сделано для того, чтобы не вмешиваться в работу Docker, RemnaNode и других контейнерных решений.

> [!IMPORTANT]
> Порты контейнеров, опубликованные Docker напрямую наружу через `-p` или `ports:`, могут проходить через `FORWARD`, а не через обычный `INPUT`.
>
> Такие порты могут не ограничиваться белым или черным списком FWMgr.

Например:

```bash
docker run -p 443:443 ...
```

Порт `443` контейнера может продолжать быть доступен независимо от whitelist FWMgr.

FWMgr в текущей реализации предназначен для контроля входящих соединений к сервисам самого хоста.

## Обнаружение Firewall

FWMgr проверяет существующую сетевую конфигурацию и может обнаруживать:

* UFW
* nftables
* firewalld
* netfilter-persistent
* Docker
* Fail2ban

Само наличие нескольких пакетов не обязательно означает конфликт.

Например, установленный пакет nftables вместе с активным UFW не всегда является проблемой.

FWMgr старается отличать просто установленный компонент от реально активного менеджера Firewall.

Если обнаружена потенциально конфликтующая конфигурация, FWMgr сообщает об этом и не пытается самостоятельно отключать чужие Firewall.

## Установка

Скачайте `fwmgr.sh` и выдайте ему права на выполнение:

```bash
chmod +x fwmgr.sh
```

Запустите от root:

```bash
sudo ./fwmgr.sh
```

В главном меню выберите:

```text
8. Добавить/обновить команду fwmgr
```

После этого менеджер можно запускать из любого каталога:

```bash
sudo fwmgr
```

## Установка Firewall

Если поддерживаемый Firewall на сервере отсутствует, FWMgr предложит установить:

* UFW
* nftables

После установки режим FWMgr остается:

```text
выключен
```

Никакие ограничения автоматически не вводятся.

Настройка списков выполняется пользователем отдельно.

## Обновление FWMgr

Если была выпущена новая версия, скачайте новый `fwmgr.sh` и запустите его:

```bash
sudo ./fwmgr.sh
```

После этого выберите:

```text
8. Добавить/обновить команду fwmgr
```

Установленная команда будет заменена текущей версией скрипта.

## Главное меню

Пример интерфейса:

```text
FireWall Manager v0.1 by MaXaoH

Firewall: установлен
Тип Firewall: nftables
Режим списков: белый
Отклонение соединений: DROP
Кол-во IP/подсетей в черном списке: 3
Кол-во IP/подсетей в белом списке: 5
Ваш IP адрес: 203.0.113.15

1. Переключить режим (выкл/черный/белый)
2. Отклонение соединений (DROP/REJECT)
3. Черный список
4. Белый список
5. Экспорт/импорт настроек
6. Сохранить
8. Добавить/обновить команду fwmgr
9. Установить Firewall
0. Выход
```

## Добавление адресов

Можно добавлять один IP:

```text
192.0.2.1
```

несколько через пробел:

```text
192.0.2.1 192.0.2.2 192.0.2.3
```

через запятую:

```text
192.0.2.1, 192.0.2.2, 192.0.2.3
```

или многострочным списком:

```text
192.0.2.1
198.51.100.0/24
2001:db8::1
2001:db8:1234::/48
```

Уже существующие записи автоматически пропускаются.

## Удаление адресов

В списках каждому правилу FWMgr присваивается номер.

Для удаления можно указать:

```text
1 3 5
```

или:

```text
1,3,5
```

Правила, созданные не через FWMgr, удалить таким способом нельзя.

## Импорт и экспорт

FWMgr позволяет сохранить текущую конфигурацию для переноса на другой сервер.

Поддерживается:

```text
1. Экспортировать в файл
2. Экспортировать в виде строки
3. Импорт из файла
4. Импорт из строки
```

### Экспорт в файл

Файл создается рядом с запущенным скриптом.

Пример имени:

```text
fwmgr_0.1_24-09-2026_19-13-42.fwmgr
```

В экспорт входят:

* версия формата;
* режим работы;
* DROP/REJECT;
* черный список;
* белый список.

### Экспорт строкой

Конфигурацию можно получить в виде одной строки и перенести через буфер обмена.

Формат:

```text
FWMGR:0.1:...
```

### Перенос между UFW и nftables

Тип Firewall не является обязательной частью экспортированной конфигурации.

Например, конфигурацию можно экспортировать с сервера, использующего UFW, и импортировать на сервер с nftables.

FWMgr применит настройки через Firewall целевой системы.

## Хранение настроек

Основные данные FWMgr находятся в:

```text
/etc/fwmgr/
```

Например:

```text
/etc/fwmgr/config
/etc/fwmgr/blacklist
/etc/fwmgr/whitelist
```

Для nftables также может использоваться:

```text
/etc/fwmgr/fwmgr.nft
```

Резервные копии находятся в:

```text
/var/lib/fwmgr/backups/
```

## Несохраненные изменения

Изменения списков сначала выполняются внутри FWMgr.

Они не применяются к Firewall до выбора:

```text
6. Сохранить
```

При попытке выйти с несохраненными изменениями FWMgr запросит подтверждение.

## Защита от одновременного запуска

FWMgr использует блокировку через `flock`.

Если один экземпляр менеджера уже запущен, второй экземпляр не сможет одновременно изменить конфигурацию.

Это защищает от ситуации, когда два процесса FWMgr одновременно записывают разные версии списков.

## Требования

Основные требования:

* Linux
* Bash
* root или sudo
* UFW или nftables
* стандартные системные утилиты Linux

Разработка ориентирована прежде всего на Ubuntu.

Основное тестирование выполняется с учетом Ubuntu 26.04.

Поддержку других дистрибутивов лучше считать экспериментальной до отдельного тестирования.

## Безопасность

FWMgr специально не использует операции наподобие:

```bash
iptables -F
```

или:

```bash
nft flush ruleset
```

Менеджер старается изменять только собственные правила.

Тем не менее любой Firewall-менеджер потенциально может привести к потере удаленного доступа при неправильной конфигурации.

Перед использованием на production-сервере рекомендуется:

1. Иметь резервный доступ через консоль/VNC.
2. Сделать snapshot сервера.
3. Проверить текущие правила Firewall.
4. Убедиться, что IP вашего подключения присутствует в whitelist.
5. В первый раз тестировать изменения на отдельном сервере или виртуальной машине.
как простой интерактивный инструмент для управления доступом к серверу по IP без необходимости постоянно работать с UFW или nftables вручную.
